# Local Markdown Knowledge Graph & Search Agent

A fully offline, local-first tool that indexes a folder of Markdown notes into a
vector database and lets you search them semantically from the command line.

- **Parsing** — reads Markdown + YAML front-matter (`python-frontmatter`) and
  splits documents into overlapping chunks.
- **Embeddings** — local [Sentence-Transformers](https://www.sbert.net/) model
  (`all-MiniLM-L6-v2` by default); no API keys, no network at query time.
- **Storage** — embedded [LanceDB](https://lancedb.github.io/lancedb/) vector
  store on disk.
- **CLI** — `typer` + `rich` interface: `scan`, `query`, `chat`, `stats`,
  `build-web`, `serve`.
- **Hybrid web UI** — a local [FastAPI](https://fastapi.tiangolo.com/) server for
  AI semantic search, with a zero-backend static fallback (MiniSearch) that runs
  on GitHub Pages. The frontend auto-detects which is available.

## Hybrid architecture

The same knowledge base is searchable in two modes, chosen automatically by the
browser on page load:

| Mode | Badge | Backend | Search quality |
| --- | --- | --- | --- |
| **Local Vector Mode** | 🟢 `● Local AI Connected` | FastAPI + LanceDB (`serve`) | AI semantic |
| **Static Cloud Mode** | 🔵 `● Static Cloud Mode` | `search_index.json` + MiniSearch, client-side | keyword |

On load, `docs/app.js` probes `http://localhost:8000/status`. If it answers, the UI
uses `POST /search` for semantic results; otherwise it fetches `search_index.json`
and does instant offline keyword search. A dropped connection mid-session degrades
gracefully to static mode without crashing the UI.

## Project layout

```
.
├── src/
│   ├── config.py       # settings loaded from .env / environment
│   ├── parser.py       # markdown front-matter parsing + chunking
│   ├── db.py           # embeddings + LanceDB vector store
│   ├── static_index.py # builds docs/search_index.json (no embeddings)
│   ├── server.py       # FastAPI backend: GET /status, POST /search (CORS *)
│   └── cli.py          # command-line interface
├── docs/               # static frontend (GitHub Pages root)
│   ├── index.html
│   ├── app.js          # hybrid detect + fallback logic
│   ├── style.css
│   ├── search_index.json   # generated by `build-web`
│   └── vendor/minisearch.min.js  # vendored, offline-capable
├── notes/              # your Markdown notes (sample included)
├── verify_setup.py     # sanity check for LanceDB + embedding model
├── requirements.txt
└── .env.example
```

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env        # then edit as needed
python verify_setup.py      # confirm LanceDB + model load
```

## Usage

```bash
# Scan the notes/ directory and (incrementally) update the index.
# Use --dir /path/to/notes to point elsewhere, --rebuild to start fresh.
python -m src.cli scan

# One-off semantic search
python -m src.cli query "how do I get started?"

# Interactive mode — ask many questions without restarting
python -m src.cli chat

# Inspect the current index
python -m src.cli stats
```

## Web UI

```bash
# 1. Launch the local AI backend (FastAPI + uvicorn).
python -m src.cli serve            # http://127.0.0.1:8000
#    GET  /status  -> {"status":"online","mode":"vector"}
#    POST /search  -> {"query": "...", "top_k": 5}
#    The UI is also served at http://127.0.0.1:8000/app/

# 2. Build the static keyword index for the offline / GitHub Pages fallback.
python -m src.cli build-web        # writes docs/search_index.json
```

Open `docs/index.html` (via the server's `/app/` route or any static host). With
the server running you get the green **Local AI Connected** badge and semantic
results; with it stopped, the page falls back to the blue **Static Cloud Mode**
keyword search.

### Deploy to GitHub Pages

Run `python -m src.cli build-web` to refresh `docs/search_index.json`, commit the
`docs/` folder, then in the repo settings enable **Pages → Source: `main` / `/docs`**.
The deployed site runs entirely client-side in Static Cloud Mode (no server needed).

## Configuration

All settings come from environment variables (see `.env.example`):
`KNOWLEDGE_DIR`, `LANCEDB_PATH`, `LANCEDB_TABLE`, `EMBEDDING_MODEL`,
`CHUNK_TOKENS`, `CHUNK_OVERLAP`, `TOP_K`, `SERVER_HOST`, `SERVER_PORT`, `DOCS_DIR`.
